# 问题库、方法库与穴位库

## 目标

基础资料只制作一次，关联时不复制正文。

- 问题库：统一用户自然语言和标准问题名。
- 方法库：管理一个可独立展示的养护方法。
- 穴位库：只管理标准定位、经验取穴、定位素材与注意事项。

## 单向职责

穴位资料回答“在哪里、怎么找”；方法与穴位的关联回答“在这个方法中如何使用”。问题与方法的关联必须保存依据类型和直接依据。

## 关联结构

```text
admin_problems
      ↕ problem_content_links（依据类型、直接原文、顺序）
admin_contents[type=skill]
      ↕ content_point_links（方法中的特有操作、顺序）
admin_points
```

关联表只存 ID 与关系属性，不复制问题、方法或穴位的完整内容。

## 审核规则

- 问题关联依据分为：原文明确推荐、案例中使用、作者观点、待人工确认。
- 问题或穴位未审核时，可用于后台组合预览，但会阻止方法发布。
- 公开接口只组装已审核的问题和穴位。
- AI 推测不是可发布的依据类型。

## 前台组装

一个方法仍对应一张结果卡片和一个详情页，不为问题、区位或穴位增加多层中间页。

首页的统一检索规则：

- 命中问题标准名、用户别名或说明时，返回该问题关联的方法；
- 命中穴位名、别名或定位说明时，返回调用该穴位的方法；
- 点击身体区位时，同时检查方法自身区位、关联问题的区位和关联穴位的区位；
- 多条路径命中同一方法时只展示一次，按匹配强度排序；
- 只使用已审核的问题和穴位关联，无匹配时如实返回空结果。

方法详情内可以紧凑定位卡片展示它调用的穴位，点击后在当前页展开，不跳转到另一层页面。
