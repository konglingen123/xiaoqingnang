# AI 搜索技术方案（路由分流 + uniCloud + 混元）

> 状态：待评审。与 `docs/features/homepage-v2.md` 配套，本文档只讲技术。
> 核心哲学：**规则优先，模型兜底**——与现有 `utils/recommend.ts` 纯规则推荐一脉相承。

## 1. 总体架构

```
用户输入（pages/ai/ai）
        │
        ▼
utils/intent.ts（规则引擎：别名词典 + 打分）
        │
   ┌────┴─────┐
   │ 命中度 ≥ 阈值            │ 命中度 < 阈值
   ▼                          ▼
utils/recommend.ts        uniCloud 云函数 ai-chat
检索方案库 → 直返             │  混元 LLM（槽位抽取 + 多轮）
【零 LLM、零延迟、            │  msgSecCheck 输入安全
 零资质门槛】                │  槽位齐 → 检索方案库 → 返回
                              │  红旗词 → 就医话术（不调 LLM）
                              └─ 均失败 → 兜底话术 + 通用方案
```

- 精确路径：纯前端，连云函数都不调。
- AI 路径：只有这一条涉及生成式 AI，是资质与备案的边界所在。
- 两条路径对页面层暴露**同一个接口**（`aiSearch(query, session)` → 统一结果结构），阶段二用规则引擎实现该接口，阶段三换成云函数实现，**页面代码零改动**。

## 2. 数据模型变更（typings/models.ts）

```ts
// RemedyPlan 新增两个检索字段（AI 匹配质量的关键，比模型本身重要）
aliases: string[]    // 口语别名：['落枕', '脖子僵', '肩颈酸'] 等
scenarios: string[]  // 场景词：['久坐', '熬夜', '吹空调', '办公室']

// AreaItem 细分（对应 homepage-v2.md 4.1 的部位体系）
// id: 'neck' | 'waist' | ... （原 5 粗分区拆细）

// 新增：AI 会话记录（阶段三，存云数据库，非本地）
interface AiSessionRecord {
  openid: string
  query: string          // 用户输入原文（合规：日志留存 ≥180 天）
  route: 'rule' | 'llm' | 'fallback'
  slots: Record<string, string>   // 槽位抽取结果
  matchedPlanIds: string[]
  ts: number
}
```

数据层同步工作：`data/remedies.ts` 全部方案补齐 aliases/scenarios；`data/areas.ts` 扩展细分部位。

## 3. 规则引擎（utils/intent.ts，新模块）

阶段二的核心，也是"本地模拟 AI 原型"的全部：

- **别名词典**：从方案的 `aliases / scenarios / name / categories` 自动生成（如「落枕」→ shoulder+tight），加一份人工维护的高频口语表（「脖子僵」「吃撑了」「手脚冰凉」）
- **打分**：命中部位别名 +3、体感别名 +5、方案关键词 +4（权重沿用 recommend.ts 的精神）
- **阈值判定**：
  - 命中 ≥1 部位 + 1 体感，或命中方案关键词 → **直返**
  - 只命中 1 个槽位 → 追问 1 轮（chips 补齐另一槽位）
  - 全部未命中 → AI 路径（阶段二：兜底话术；阶段三：LLM）
- 红旗词检测（高烧/剧烈/出血/晕倒/胸闷/呼吸困难…）在规则引擎**最前面**执行，命中直接返回就医话术。

## 4. LLM 接入（阶段三）

### 4.1 服务与模型

- uniCloud 云函数 `ai-chat`（与未来档案云同步共用同一空间）
- 模型：**腾讯混元**（`hunyuan-turbo` 起步；理由：微信生态内，算法备案材料官方可提供，合规路径最短）
- 密钥只存在于云函数环境变量，前端不接触

### 4.2 Prompt 骨架

系统提示词要点：

1. 定位：小青囊养生方案的**检索助手**，不是医生
2. 禁令：不得给出诊断、用药建议、疾病名称；不回答与身体舒缓无关的问题
3. 槽位抽取：输出严格 JSON（见 4.3），不得输出槽位之外的自由建议
4. 红旗词列表：命中 → 输出 `RED_FLAG` 标记，由云函数替换为固定就医话术
5. 推荐理由：≤50 字，只解释"为什么推荐这个方案"，去疾病化语言

### 4.3 结构化输出（JSON Schema）

```json
{
  "slots": { "area": "neck", "feeling": "tight", "preference": "不想泡脚" },
  "needMoreInfo": false,
  "followupQuestion": "这个紧绷是什么时候开始的？",
  "chips": ["久坐后", "睡觉后", "一直都有"],
  "matchedPlanIds": ["warm-neck", "cloud-hands"],
  "reason": "温敷能让紧绷的颈肩慢慢松开"
}
```

- 槽位状态机在云函数维护（缺部位/体感 → 追问，≤3 轮；槽位齐 → 用 matchedPlanIds 检索方案库，**方案正文始终来自本地数据，不由 LLM 生成**）
- LLM 只产三样东西：槽位、理由、追问文案；健康内容零生成

### 4.4 流式方案

- 小程序端：`wx.request` 开启 `enableChunked` 分块传输，或 WebSocket；H5 端用 SSE
- uniCloud URL 化的流式返回需要验证（微信侧对小程序长连接有平台限制）
- **第一版建议降级方案：一次性返回完整结果 + 前端打字机逐字渲染**。实现简单、体验接近流式、成本相同，先落地再评估真流式

### 4.5 多轮会话

- 会话上下文存云数据库（`ai_chat_sessions` 集合），前端只带 sessionId
- 会话超时 30 分钟过期；用户输入原文随会话留存（合规要求 ≥180 天日志）

## 5. 内容安全与合规红线（新增红线 4）

1. **输入安全**：用户输入先过微信内容安全 API（`msgSecCheck`，云函数内调用），违规直接拒绝
2. **输出过滤**：LLM 输出过 `BANNED_WORDS` 禁用词过滤，命中词替换或重试
3. **词表三处同步问题**：禁用词表现在有 3 个位置——`data/compliance.ts`、`scripts/check-content.js`、云函数。策略：**云函数目录复制一份 compliance.ts 公共模块**，并扩展 `check-content.js` 扫描云函数目录，保证三处一致
4. **红旗词表**：固定就医话术，不经过 LLM，不可被 prompt 覆盖
5. **AI 标识**：AI 路径的结果卡片与每条 AI 输出均标注「内容由 AI 生成」（微信强制）
6. **日志**：会话日志留存 ≥180 天，提供投诉入口（锦囊页）

## 6. 资质与备案（个人主体现状）

| 阶段 | 功能形态 | 需要的资质 |
| --- | --- | --- |
| 阶段二 | 规则版搜索（无 LLM、无 AI 标识） | **无新增资质，个人主体可直接上架**（功能命名避免宣称 AI 生成） |
| 阶段三 | 真 LLM 接入（内测 / H5） | 企业主体 + 小程序备案 |
| 阶段四 | AI 上架微信 | 「深度合成-AI问答」类目 + 混元算法备案材料（官方提供）+ 网信办生成式 AI 备案（周期 3~6 个月，需安全评估报告、1 万词拦截列表、2000 题测试集） |
| 会员 | 付费功能 | 虚拟支付类目；**iOS 端禁止虚拟支付**，仅安卓/H5 售卖 |

## 7. 成本控制

- 路由分流是最大的控本手段：高频精确 query 全部零成本
- 免费额度（每天 3 次 AI）+ 会员
- 同 query 结果缓存 15 分钟（云函数内存或数据库）
- 模型从 `hunyuan-turbo` 起步，输出限长，槽位抽取短输出
